# vault-reuse — solution

## TL;DR

The Ansible vault password is generated by a script from committed, non-secret
project metadata (`project`, `deploy_env`), so it is fully reproducible from the
repo. Rebuild the password, decrypt `group_vars/secrets.yml`, get the flag.

## The misconfiguration

`ansible.cfg` sets `vault_password_file = bin/get-vault-pass.sh`. That helper
does not read a secret — it derives the password from `group_vars/all.yml`:

```sh
proj=$(awk '/^project:/ {print $2}' all.yml)     # kekeli
env=$(awk '/^deploy_env:/ {print $2}' all.yml)   # staging
printf '%s-%s-vault-v1' "$proj" "$env"           # kekeli-staging-vault-v1
```

A vault whose password is a deterministic function of committed, non-secret
values provides no protection — anyone with the repo recomputes it.

## The vault envelope (ansible-vault-styled, stdlib-only)

```
line 1: $VAULT;1.0;PBKDF2-SHA256
line 2: base64( salt(16) + iters(4, big-endian) + ciphertext )
key     = PBKDF2-HMAC-SHA256(password, salt, iters)
stream  = SHA256(key || counter)  for counter = 0, 1, 2, ...
plaintext = ciphertext XOR stream
```

## Attack

1. Read `project` and `deploy_env` from `group_vars/all.yml`.
2. Rebuild `password = "<project>-<deploy_env>-vault-v1"`.
3. Base64-decode line 2 of `secrets.yml`, split salt/iters/ct, derive the key,
   and XOR-decrypt.

## Run

```
python3 solve.py
```

Output:

```
[+] derived vault password: kekeli-staging-vault-v1
[+] FLAG = NCTF{ansible_vault_password_was_derivable_4e77}
```
